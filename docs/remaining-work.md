# Remaining work after offline completion

Version 0.4 completes the authorized credential-free engineering pass. It is not an MVP or production release. The [backlog](backlog.md) retains milestone exits and acceptance criteria. Existing components should not be rebuilt; remaining steps are controlled integration and external acceptance.

1. **Choose deployment identity and trust configuration.** Provide the intended issuer/audience, trusted human subjects/roles, tenant/repository/team scope, secret/key custody, retention policy and deployment target. Assemble the tested factories with those choices; default readiness/publication stay disabled until accepted. Ephemeral test identities are not real human identity.
2. **Authorize a bounded model evaluation.** Supply model credentials and an explicit model/budget/pricing decision. Freeze independently authored/adjudicated cases before running. Exercise Responses token preflight, durable calls, timeouts and actual usage; preserve first failures. No automatic uncertain retry exists. General intake remains conservatively tier 3 until justified policy changes are separately reviewed.
3. **Accept repository-aware semantics.** Authorize read access and exact repository/commit scope. Exercise the GitHub reader, indirect-injection cases, relevance, unsupported claims and decomposition against the actual inference path. Static matching and mock provider results do not prove quality.
4. **Authorize controlled Linear acceptance.** Confirm the organization/app actor/team/project/label mapping and desired OAuth scopes. Account/key presence has been located in the sibling repository; no additional copy is needed for discovery. Explicit ticket-write authorization is still required. Assemble the tested native service with the deployment authority and perform a minimal approved live plan with actual provider receipts and reconciliation evidence. Do not turn on the public publish endpoint merely because a key exists.
5. **Integrate the public v2 consumer into Delivery OS.** Obtain authorization for the downstream repository scope and agree issuer keys, expected digest channel and tier policy. Adapt the public artifact into Delivery OS's own model/store, invalidate actual stale planning assumptions, and exercise exact-digest intake. The reference consumer is ready for this work but is not installed there.
6. **Run hosted/deployment acceptance.** Supply a Git remote/hosting destination. Run the checked-in Actions matrix, service tests and container job. Deploy authentication/TLS/access policy, external secret custody, physical-retention/incident procedures and production observability; run recovery there. Local container backup evidence does not establish a production recovery objective.
7. **Finish M1/M3/M6 quality and human acceptance.** Freeze at least 40 separately authored semantic cases across all ten categories, run actual bounded inference, adjudicate precision/recall, ambiguity/false resolution, criteria/decomposition/grounding/risk and retain configurations/latency/cost. Obtain real human editing-effort/usefulness evidence. Publish/tag an MVP or portfolio acceptance release only when its gates pass.

These steps include deployment-specific engineering and independent validation. They are not presented as capabilities blocked only by a missing password. No live tickets, model spending, credential setup, sibling modifications or hosted publication were authorized in this initialization. All offline deliverables and commands are in [validation](v04-validation-record.md); precise product limitations are in [status](implementation-status.md).
