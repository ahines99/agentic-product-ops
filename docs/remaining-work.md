# Remaining implementation sequence

Version 0.2 is an offline service expansion, not an MVP. The [backlog](backlog.md) retains explicit acceptance criteria and dependency IDs. No live credentials or paid runs are authorized by initialization.

1. **Durable role execution (B11-B14, I03, I05).** Persist immutable analyst/decomposer/reviewer inputs, outputs, findings, prompt/config IDs, usage and estimated cost. Invoke roles through Temporal activities with bounded retries and timeouts; restart without losing evidence or quietly repeating billable work. Keep proposal authority in deterministic validators.
2. **Clarification and revisions (B06, B08-B10, I01-I03).** Resume analysis from authorized clarification receipts, create a new immutable specification, rerun review, bound revision attempts, and invalidate prior approval. Exercise answer/approval races, stale decisions, timeout, cancellation and revocation. Current clarified revisions intentionally remain blocked.
3. **Production identity (B09, B29, I01).** Authenticate real human/tenant identity, provision trusted scope and approver/security roles, audit authorization changes, and support revocation. Bind receipts to exact reviewable artifacts. Test wrong-tenant/role/replayed credentials; default deny until configured. This requires an identity/deployment choice and eventual authorized credentials.
4. **Real model adapter and M1 evidence (B11-B17).** Add structured inference transport with verified token bounds, provider timeout/retry rules, request IDs and accounting. Obtain separately authored adjudicated requirements/ambiguity cases. Run only with an explicit budget and credentials; preserve first failures and denominators. A scripted role runner does not satisfy semantic acceptance.
5. **Repository grounding (B18-B23).** Connect authorized GitHub reads, pin immutable commits, reject partial/mismatched snapshots, evaluate relevance/coverage, and test indirect injection with the actual inference path. Keep inspected code inert. Local AST metadata is advisory and cannot by itself establish correct component selection.
6. **Decomposition quality (B24-B28).** Evaluate coherent ticket boundaries, supported acceptance criteria, dependency ordering, semantic overlap and justified risk on independently reviewed repository-aware cases. Preserve blockers and research-only outcomes rather than forcing proposals through gates.
7. **Live Linear boundary (B29-B35).** Implement least-privilege OAuth and tenant metadata, exact plan approval, native issue/dependency mappings, persisted authorization/revocation and reconciliation. Connect workflow activities only after controlled fault tests. With separately authorized live writes, exercise expiry, concurrent duplicates, lost/late responses, partial batches and cancellation; preserve actual provider evidence.
8. **Delivery OS intake (B36-B37).** Agree a public adapter in Delivery OS that verifies trusted issuer/transport, schema, expected approved digest, exact revision, unresolved questions and risk tier. Store immutable intake in its own persistence, preserve the original specification, and invalidate stale plans. Exercise the actual consumer; do not import or share database classes.
9. **Operations and deployment (I04-I05).** Exercise Docker/Compose and hosted CI, pin deployment artifacts, wire honest dependency readiness, add trace/export/retention and credential handling, and test backup/recovery. Measure model, human-wait and publication latency separately. Local development-server evidence does not establish production readiness.
10. **Release evaluation and usefulness (B38-B40).** Freeze at least 40 separately authored semantic cases across specified categories, preserve failures/configuration/snapshots, measure quality/safety/reliability/cost/latency, and obtain human editing-effort/usefulness evidence. Publish an accurate end-to-end case study and tagged release only after its gates pass.

Steps include additional offline engineering as well as external prerequisites. They are not all blocked solely by credentials: orchestration, revision wiring, stronger tests and observability still require implementation. Independent authoring and real human validation cannot be manufactured by repeating this session's fixtures. Live publication, downstream repository changes and deployment require their own concrete authorization.
