# ADR-012: Signed public handoff and independent reference intake

Status: accepted, 2026-09-29. Extends ADR-005 and preserves ADR-008's actual Delivery OS integration gate.

The v2 handoff includes the complete approved WorkSpecification, native publication plan, successful operation receipts, dispatch-authorization timestamps and clarification receipts. Export reads these from Product Ops persistence under current scope, cancellation and durable authority checks. Historical write authorization is checked at dispatch time; a late provider response does not extend approval. Tier 2/3 work cannot be exported. An injected Ed25519 key signs a domain-separated payload digest with issuer, audience, key ID and a bounded expiry. No signing keys are discovered, persisted in artifacts or provided to models.

The separate `product_ops_handoff` package implements a public JSON Schema consumer reference. It imports no Product Ops internals. It validates signature trust, expected approved digest, tenant/team/repository/policy scope, nested hashes, ambiguity, risk, traceability, dependencies, native target mapping and publication/dispatch evidence. It rejects mock evidence by default. Its SQLite database is a **contract-test reference store**, not Delivery OS production persistence. It refuses to share a database with Product Ops, retains original envelope bytes immutably, tracks accepted revisions, and marks older reference work items superseded. It never executes work or starts a Delivery OS worker.

The schema is generated and frozen in the package. CI checks schema drift. Tests use ephemeral signing keys and mock publication; an isolated interpreter verifies that consumer import does not import the producer. New signed revisions invalidate old intake; signature and unsafe-payload tests use separately configured consumer trust. Cryptographic validity does not prove semantic quality or human usefulness.

This supplies a concrete reviewable contract and executable consumer reference while respecting the instruction not to execute untrusted repository code. The adjacent Delivery OS repository was not modified, imported or executed. Installing an adapter into its actual intake, choosing deployed issuer keys and validating real approved Linear evidence remain an explicit cross-system acceptance gate. No shared database, internal model import, execution responsibility or simulated production claim is introduced.
