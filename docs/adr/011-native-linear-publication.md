# ADR-011: Native Linear plans, encrypted OAuth, and conservative reconciliation

Status: accepted, 2026-09-29.

Version 1 plans and the offline demo remain stable. Version 2 plans include issue creation and native blocking relations in one reviewed mutation budget. Explicit server configuration maps local team/project/label identifiers to provider UUIDs and pins the organization and actor. Models cannot supply that mapping. Each target UUID has provider-required version/variant bits and is deterministically derived from its logical operation digest; it is not a random secret or a claim that the provider guarantees exactly-once creation. Relations point from prerequisite to dependent and follow both issue creates. Epic-to-project conversion is denied until an explicit product mapping exists; projects and labels may only be pre-existing mapped objects.

The API exposes the rendered plan and requires its digest when approving native publication. It stores the exact plan and grant-bound approval. The native publisher verifies current specification, recorded review, approval, plan, scope, mutation count, cancellation and revocation. It commits UNKNOWN before dispatch. Metadata checks verify tenant/actor/team/project/labels; a second authorization check occurs after these reads immediately before mutation. A separate immutable dispatch-authority receipt preserves the authorization timestamp. Late successful responses are recorded; they cannot authorize subsequent writes.

Reconciliation reads the predetermined issue/relation UUID and checks exact content, destination and labels. An absent object, unavailable lookup, normalization difference or conflicting body leaves UNKNOWN. There is no automatic recreate, delete, rollback or republish generation. A failed preflight without a dispatch receipt cannot be retried through reconciliation. This deliberately trades availability for prevention of uncertain duplicate writes. Linear Markdown normalization may require operator review; tests cannot establish its live canonicalization behavior.

OAuth uses app-actor PKCE S256, session-bound single-use state, fixed HTTPS callback/origin, explicit scopes and no implicit refresh retries. Default scopes are read plus issue creation; native relations require explicitly configured write scope. Tokens/verifiers are AES-256-GCM encrypted with workspace/identity/revision/key binding. Master keys are injected, not discovered. Encryption-key rotation retains old ciphertext and requires a deployment retention/key-destruction decision. Unknown exchanges or refreshes hold for reauthorization; provider refresh grace is not used for blind retries.

The API live-publication route remains disabled. Native orchestration is exercised using MockTransport, ephemeral identity and local storage. Existing Linear credential availability does not authorize publication. No external ticket, webhook, OAuth application or model call was created by this pass.

References consulted: [official Linear OAuth](https://linear.app/developers/oauth-2-0-authentication), [GraphQL guide](https://linear.app/developers/graphql), [official SDK schema](https://github.com/linear/linear/blob/master/packages/sdk/src/schema.graphql). The SDK schema documents client-supplied IDs for issue and relation creation; the schema was read as data and no SDK/repository code was executed.
